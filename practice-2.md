Типичный цикл CI‑CD для небольшого проекта на C#:
1) Коммит и отправка код в репозиторий (локальные изменения разработчика пушатся в удаленных репозиторий на github)
2)Автоматический запуск конвейера после получения нового коммита CI cистемой(может быть GitHub Actions, GitLab CI, Jenkins или Azure DevOps).Первоначально выполняется восстановление зависимостей в проекте и его сборка.Инструмент dotnet скачивает необходимые NuGet-пакеты и компилирует проект. 
(пример CI pipline)
- name: Restore dependencies
  run: dotnet restore
- name: Build
  run: dotnet build --no-restore
3)После успешной сборки CI переходит к выполнению тестов. Для проектов на C# обычно используются тестовые фреймворки xUnit, NUnit или MSTest. Они запускаются через команду dotnet test
4)CI-система собирает финальные артефакты проекта. Обычно это подготовленная релизная сборка с помощью команды dotnet publish, содержащая все необходимые библиотеки и файлы, чтобы приложение можно было запускать на сервере.
5)На следующем шаге артефакт помещается в Docker-образ. В Dockerfile указываются базовый образ .NET Runtime, рабочая директория и команда запуска приложения.CI-система собирает образ и загружает его в контейнерный реестр, например Docker Hub, GitHub Container Registry или Azure Container Registry.
6)После сборки Docker-образа или статических артефактов они автоматически отправляются на тестовый сервер. Для развёртывания могут использоваться Docker Compose, Kubernetes, Azure App Service, GitLab CD или Ansible.риложение запускается в окружении, максимально приближенном к продакшну и проводится его тестирование 
7)Просматриваем логи пайплайна и результаты тестов.
8)Деплой в продакшн. В зависимости от архитектуры проекта это может быть выкладка Docker-контейнера в Kubernetes, обновление приложения в облачных службах, развёртывание через SSH на физический сервер или применение стратегий автоматического обновления
